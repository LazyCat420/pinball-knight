The knight is clean: grid commit + rot ban, shipped

Why imported sprites looked dirty, the five treatments measured against the hand-written painter, and the before/after of the fix now in public/sprites.

idle, camera-facing, 10× — before / shipped / painter, through the game's real crush

Verdict: isolated-pixel noise 42.3 → 35.8% (S) and 35.6 → 28.0% (N); zombie-green contamination 11.9 → 5.3% and 12.6 → 3.5%. On the away facing the shipped sheet is now cleaner than the procedural painter. Every number is the production importedPaints → crushToGrid path at the shipped rung.

diagnosisWhy it was grainy

The generator emits a continuous-tone rendering of pixel art — the old sheet held 43,637 distinct colours. At load, every texel snaps to the nearest of the 32 Cold Crypt colours under a luma-weighted metric (0.3 / 0.59 / 0.11). Smooth silver gradients straddle palette boundaries, so neighbouring texels coin-flip between entries; and because the metric nearly ignores blue, warm-grey armor kept matching the rot-green ramp — about 12% of the knight's crushed pixels were literally the zombie's colour.

what shippedThe recipe, and what it is not

  • Grid commit (commitToGrid, now opt-in per sheet via the sidecar): k-centroid reduce to the final texel count → snap to the palette → evict to the 20-entry lock → re-up on a ×8 lattice. The sheet the artist reviews is, pixel for pixel, the sheet the player sees at every camera rung.
  • Material ban (new): the sidecar declares "bans": ["rot"] — the knight owns no rot, so those four entries are remapped to their nearest allowed colour before the evict. Material intent is metadata; no colour-space trick recovers it from pixels.
  • The sheet itself went from 43,637 colours / 1.0 MB to 20 colours / 73 KB, and the gate re-measures it as a ×8 pixel grid at 100% confidence.

  • Quantize-only did nothing — pre-snapping every pixel measured worse than the raw sheet, because the runtime downscale re-blends and re-rolls the snap. Order is everything: reduce first, then snap.
  • “Base colours first” (k-means-12, then commit) edged plain commit by 0.2pp but smeared the chest strap — the commit's own per-texel k-centroid already is that reduction, done at the right resolution.
  • Grading the green out of the source measured identical to no grade. Only the explicit family ban moved the rot number — which is why the fix is metadata, not a filter.

tradeOne honest cost

A committed sheet is sized for the widest camera rung, so the knight renders ~15% smaller than the old import, which oversized by filling the cell at the default rung. That is the price of “1:1 texels at every rung” — the old size was never stable across rungs anyway. If he reads too small in play, the sidecar's scale field is the sanctioned lever.

the mapAnd the grainy floor?

Different mechanism. The screen pass re-quantizes the whole lit frame every frame, and its Bayer dither breaks lighting gradients into the stipple you see on stone. Since 07-30 it can only step within a colour's own ramp (the family-hopping confetti is already fixed), so what remains is the intended retro texture — and it is a settings toggle (dither, default on). Turn it off in the options menu to compare; if the floor still reads dirty with it off, that is floor-painter ramp authoring, not a filter bug.
